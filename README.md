# Bueeld Lab — AI co-founder prototype

Bueeld Lab is a standalone, chat-first prototype built for the **Build Your AI Co-Founder Hackathon** on September 28, 2026. Lia is an AdaL-powered AI co-founder. A founder can discuss an idea or supply project context, turn Lia's answer into a proposed next mission, approve it, and return with evidence. Lia's chat replies, learning reviews, and source analyses come from live AdaL requests. A separate, clearly labelled fictional guided example uses pre-written replies and makes no AI calls.

The welcome screen offers **Try Lia in 2 minutes**, a fictional guided example without an account or live AI, and **Create a Lab account**. Signup opens a four-step, one-question-at-a-time chat introduction: idea or existing project, audience, evidence, and current obstacle/desired next move. Each step offers suggested answers, free text, Back, and Skip. Lia receives one founder brief at the end and proposes a first mission in one AdaL call. Signed-in chat, partial setup answers, selected source summaries, and mission history save automatically. A guest can explore locally; if a hidden guest draft exists, the welcome screen asks them to choose **Restore draft** or **Start fresh** before sending. Copying a guest chat into an account requires a separate, explicit **Save now**. **Analyze a project** opens **Sources**, with the fictional sample, local files, and public GitHub before account connectors; the composer **Connectors** button jumps directly to those cards. The optional **Decision canvas** turns a conversation into a separate structured checkpoint with two paths, a risky assumption, an experiment, a human choice, a success bar, and a reassessment.

## Demo: from context to a mission

1. Use **Try Lia in 2 minutes** to show a fictional four-step example: project → proposed mission → human approval → result → learning. Choose **Target missed** to show how the next test changes. This adds no XP or stored data. [Presentation and offline backup guide](DEMO.md).
2. For live analysis, choose **Analyze a project**, then analyze the fictional sample, a local file, or a public GitHub repository. Source claims cite supplied excerpts; they still need human verification. Select **Use this summary in chat** to reuse a summary.
3. Use **What Lia knows** above the composer to save four editable fields: project, target, goal, and blocker. Guest memory stays in this browser; signed-in memory syncs per account and is reused across chats. Unsaved edits are not sent.
4. On a reply, choose **Start a mission**, review or edit the proposed text, then **Approve & start mission**. The mission stays inside the conversation. Approval does not execute anything outside the prototype.
5. Choose **Help me do this** to ask Lia for a practical interview guide, experiment protocol, message draft, or checklist. **Copy response** copies the deliverable; no message is sent externally.
6. **Add my result**, select the evidence area and observed outcome, and save. Mark fictional observations as demo evidence. Confirm completion separately; real self-reported tests earn Lab XP even when the target is missed.
7. Choose **Review result with Lia** for an AdaL-generated assumption → observation → decision → next-test card. Missed and inconclusive targets cannot receive a continue recommendation. Preparing the next mission uses the review and preserves any existing composer draft.
8. **Progress** opens a centered summary with history, areas explored, and evidence-based milestone badges. Fictional results earn no badges or rewards. XP and drops are demonstration values, not redeemable rewards or verified traction.

For a Bueeld-specific conversation without sample data, choose **Describe an idea** or the **Work on Bueeld** starter. Starters send in one click. The Bueeld starter describes the product problem but treats customer results and traction as unknown. Keep the fictional Atelier Loop workspace separate from factual Bueeld claims.

You can export the chat and mission as Markdown or open the optional **Decision canvas**. For a signed-in founder, **New chat** saves the current conversation and switches to a blank one without a discard confirmation; if saving fails, it keeps the current chat. Under the composer, the signed-in save indicator shows **Saving to Lab…**, **Saved to Lab**, or **Lab save failed** with **Retry save**. A guest's **New chat** asks before discarding local work. A hidden guest draft instead has an explicit **Restore draft** / **Start fresh** choice. The canvas can copy the founder's completed chat messages into a brief, but observed evidence must be added separately. The human chooses an option and approves the success bar before a structured reassessment.

## Sources: what works

- **Fictional workspace:** four clearly marked Atelier Loop records are analyzed together in one AdaL request. They illustrate source attribution without pretending a pilot happened.
- **Local file import:** choose a `.txt`, `.md`, `.csv`, `.json`, `.eml`, or `.ics` file up to 64 KB, or a PDF up to 8 MB. PDF.js extracts selectable text in the browser from up to 12 pages; image-only scans need OCR first. Excerpts sent to AdaL are limited to 8,000 characters and require an explicit **Analyze** action. DOCX is not supported. A Gmail, Google Drive, Google Calendar, or Notion card can also guide a manual export flow.
- **Public GitHub:** enter `owner/repo` or a public GitHub repository URL. The server reads public repository metadata and its README, then asks AdaL to analyze them. It does not read a private repository, source tree, or personal GitHub account.

The four workspace cards — **Gmail, Google Drive, Google Calendar, and Notion** — have per-tester, read-only OAuth code paths: connect, list recent items, import only items selected by the visitor, and disconnect. Provider tokens remain in a short-lived server-memory session. Availability is reported live by `/api/connectors/status`. Google OAuth setup and real-account tests must be completed before the Gmail, Drive, or Calendar cards can be described as working for public visitors; Notion also needs a registered callback and a real authorization test. Their manual export path remains usable. See [OAuth setup](OAUTH_SETUP.md) for the exact environment variables, callbacks, and provider requirements. The private hackathon GitHub repository cannot be used in the public GitHub reader.

For each source request, AdaL separates cited facts from assumptions and open questions, and proposes a risk, a next action, and the evidence needed to assess it. Source text is untrusted input. A citation points to supplied text, not independent proof that the statement is true.

## Run locally

Requirements: Node.js 20+ and the AdaL CLI installed and signed in, with available usage through AdaL or a connected eligible subscription. This prototype used the founder's **existing ChatGPT subscription connected to AdaL through OAuth**; no new paid AdaL subscription was started. Availability and usage limits depend on that connection.

From this directory:

```sh
ADAL_MODEL=chatgpt_web-gpt-6-luna node server.mjs
```

Open `http://127.0.0.1:4173`. Set `PORT` for another port. `ADAL_MODEL` selects a connected model explicitly; omit it to use the AdaL model already selected on this computer. The server binds to localhost by default.

The Node server serves the UI, handles optional Lab accounts, and calls AdaL for chat, source analysis, structured plans, mission learning reviews, and reassessments. Every request uses the dedicated Lia role in `adal-role.md` through AdaL's `--prompt-file`, so replies are complete application answers rather than coding-agent progress updates. Lia responds in English by default, even to messages written in another language. She switches only after an explicit language request and keeps that requested language until the founder changes it. When context is missing, Lia asks one short question about one missing fact, then waits for the answer before continuing. Clarification replies stay under 60 words and reuse facts already supplied; once enough context is available, Lia answers directly or proposes the next mission. AdaL's built-in tools are disabled for these requests. The prototype does not send messages, deploy code, edit external apps, or perform other outside actions. It permits one AI call at a time and enforces a **shared** maximum of 1,000 AI calls by default across visitors and restarts using the Git-ignored private `.data/demo-usage.json` counter. `GET /api/demo/usage` reports used and allowed calls; chat, mission reviews, and source analysis spend from the same allowance. The **Privacy & AI use** disclosure shows calls remaining, and a visible low-quota alert appears when two or fewer remain. At zero, new AI requests are disabled while saved chats and missions remain available. `MAX_AI_CALLS` can set a different non-negative cap; `0` disables AI calls. Blank or invalid values use the 1,000-call default. Public GitHub lookups have a separate `MAX_GITHUB_FETCHES` cap (default 20). Requests have size and time limits. A structured plan ID expires after one hour and does not survive a server restart.

Run `node --test *.test.mjs` from this directory for isolated account, connector, quota, and chat integration checks. The chat test uses a fake AdaL executable and consumes no live AI calls.

## Data and limits

- Extracted local text, selected connected-source excerpts when OAuth is configured, and fetched GitHub content are sent to AdaL only after the founder clicks an **Analyze** button. The server does not persist raw provider payloads or OAuth tokens; provider tokens exist only in temporary server memory. Signed-in Lab accounts automatically persist conversations, in-progress setup answers, selected source **summaries**, and mission tracker records. Guest drafts are never sent to the account store unless the founder copies and saves them. A chat reply may itself contain source-derived text, so review private material before including it in a conversation.
- Full source analysis cards live in page memory. Guest selections are lost on reload; the signed-in active conversation automatically hydrates up to three selected summaries on reload, and a reopened saved conversation restores them too, without the original raw excerpts. Selected summaries, not raw source text, accompany later chat requests. Removing a summary does not erase source-derived claims already written in a local or saved chat; **New chat** starts a separate conversation, and saved conversations remain available until deleted in Account.
- Guest chats and drafts remain in browser localStorage and are hidden after sign-out until explicitly restored. A signed-in founder can reopen prior chats; autosaved threads include a pinned mission, up to three selected source summaries, and in-progress setup answers. Mission records, their learning reviews, and explicitly saved project memory sync per account; points, drops, and areas explored are calculated from recorded evidence rather than stored as independent awards. Account-scoped browser drafts are cleared on sign-out. Saved account data live in ignored `hackathon/.data/accounts.json` on the demo server, separate by user ID. Passwords use salted scrypt hashes; no e-mail is sent and there is no password recovery in this prototype. A founder can delete their Lab account from the account panel after entering the Lab password and confirming the action, removing its chats, mission history, and connected-source sessions from the active store. Lab sign-in lasts 30 days and survives page reloads and server restarts. Authentication records use hashed session IDs in the private, Git-ignored `.data/auth-sessions.json` store; sign-out and account deletion revoke them. Session cookies are scoped by server port so separate local demos do not replace one another’s login. Anonymous sign-in sessions still expire after two hours. OAuth provider tokens stay in memory and expire within one or two hours; they are never written to the authentication store. A request for a reply sends the new message, up to 12 earlier messages, saved project memory, the pinned mission if any, and selected source summaries to AdaL; the connected ChatGPT account may process them. The separate Decision canvas maintains its own local journal.
- Lia may take several seconds or return a usage, timeout, or response error. The UI shows an error and allows retry rather than presenting a scripted reply as live AI.
- The Atelier Loop scenario, interviews, expressions of interest, and sample metrics are fictional demonstration data. The prototype does not claim a real pilot, completed mission, external execution, or customer validation.

## Scope and provenance

Bueeld already helps incubators turn scattered startup updates into structured context and a human-approved next mission. This folder is a **new application in a separate worktree** for the hackathon. It borrows Bueeld's product problem and brand context. The production Bueeld UI, Firebase services, accounts, and API keys remain outside this prototype; no production Bueeld code is modified.

AdaL was used to design `decision-schema.json`, review the API server, and help with the explicit human option choice. At runtime it generates live chat replies, sourced analyses, structured plans, mission learning reviews, and reassessments. The project follows the **Make It** track and uses AdaL as its sponsor tool. It does not claim to use Ask The W or Tenki.

The GitHub repository for this hackathon copy is **private**. A reviewer needs explicit access to inspect the source. A temporary Cloudflare tunnel is used for the live demo; it lasts only while the local server and tunnel processes run and has a shared 1,000-call AdaL cap by default. OAuth callbacks require a stable, registered origin; the random tunnel URL cannot serve as a permanent Google OAuth callback. `lab.bueeld.com` is the intended stable address if deployment and DNS setup complete.
